# Assets inventory

This is the inventory required by EPIC-26/T-262 (US-129): what each file under
`assets/` is, where it came from, and how it may be used. It exists so
downstream work (Desktop layout — US-053/T-186; accessible navigation —
US-055/T-188; and anything else that reads "the identity" from this
repository) has one place to check instead of guessing from the filenames.

See also `docs/product/brand-identity.md` for the identity these assets
illustrate (name, tagline, mascot concept, sail + Git-graph visual concept)
kept as a separate, prose document distinct from this file inventory.

## What "reference" means here

Everything in this directory is a **visual reference for design work**, not a
**functional requirement**. A visual reference says "this is what the
identity has looked like so far, for inspiration and continuity." A
functional requirement is a PRD/backlog acceptance criterion — e.g. "the
Desktop graph view must show branch/tag/stash panels" (US-053 criterion 1) —
which lives in `docs/product/GitSail_PRD_v0.1-v1.0.md` and
`docs/product/GitSail_Product_Backlog_v1.0.md`, never in this directory. A
task that cites a mockup (e.g. US-053 criterion 3: "Mockup Desktop orienta
identidade própria; adaptação funcional não copia assets ou UI proprietária")
must treat the mockup as inspiration for GitSail's *own* look, not as a
pixel-accurate spec, and never as license to copy another product's
proprietary UI that the mockup may visually echo.

## Rights and availability — not verified

**Trademark registration and copyright/usage-rights availability for the
name "GitSail" and for these specific asset files have not been verified by
anyone working in this repository.** No search of any trademark register,
no licensing/rights check on the source images, and no legal review has been
performed as part of this inventory or as part of EPIC-26. Concretely:

- Do not describe "GitSail" or these logo/mockup files, in any document or
  release material, as cleared, registered, or verified available for public
  use, until an actual trademark/rights check has been performed and
  recorded.
- Until that confirmation exists, treat the name, logo, and mockups as
  **internal working material**: fine to keep evolving the product's
  identity around them, not fine to assert as a settled, rights-cleared
  brand in anything aimed at the public (a public release announcement, a
  package registry listing, a trademark filing, etc.).
- This mirrors the same caution `docs/product/brand-identity.md` states for
  the identity concepts themselves, and the backlog's open-decisions entry
  "Marca/pacotes/domínios e uso dos assets" (`docs/product/GitSail_Product_Backlog_v1.0.md`
  §8), which this inventory satisfies without closing — that evaluation is
  still explicitly pending, to be done before any public branding
  announcement.

## Keeping this table current

Add a row whenever a new brand/mockup asset is added under `assets/`, and
update the "Status"/"How to use it" columns if a file's role changes (e.g.
once a mockup is formally superseded by an implemented, reviewed design). Do
not delete or overwrite an existing original asset to "update" it — add the
new file alongside it and update this table to say which one is current.
